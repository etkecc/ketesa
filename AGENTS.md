# Ketesa

Admin UI for Matrix homeservers: Synapse's admin API plus Matrix Authentication Service (MAS), no backend of its own. React 19, react-admin 5, MUI 7, TypeScript, Vite, Yarn 1.22. The browser calls the homeserver directly, so changes have to work on plain Synapse and on MAS-backed deployments.

## Commands

- Full check: `just test` # comment-guard, eslint --fix, prettier --write, tsc, vitest; rewrites files
- Scoped test: `yarn test src/utils/mxid.test.ts`
- Typecheck: `yarn typecheck`; lint: `yarn lint` (`yarn fix` applies fixes)
- Build: `yarn build --base=./` # `--base=/admin/` for the subpath build; base path is baked in
- Dev stack: `just run-dev` # Synapse :8008, MAS, Element :8080, app :5173; login admin/admin; `just stop-dev`, `just logs-dev`
- Prerequisites: Node LTS, Yarn 1.22, Docker (the justfile calls `docker-compose`). No app env vars: runtime config comes from `config.json` or `/.well-known/matrix/client`.

## Layout

| Path | What lives there |
|---|---|
| `src/App.tsx` | `<Admin>` wiring: providers, resources, custom routes, `disabled.*`/MAS gating |
| `src/resourceMap.ts`, `src/providers/data/index.ts` | resource name -> API descriptor; `initResources()` swaps entries when MAS is active |
| `src/providers/data/` | `synapse.ts`/`mas.ts` CRUD, `*-actions.ts` one-shot admin calls, `lifecycle.ts` user/room side effects, `etke.ts` etke.cc platform |
| `src/providers/auth/index.ts` | password, access-token, OIDC/MAS login and logout; writes session state |
| `src/resources/<name>/` | one directory per react-admin resource, everything re-exported from its `index.ts` |
| `src/i18n/<locale>/` | 10 locales; `i18n-keys.test.ts` enforces identical key sets |
| `src/components/etke.cc/` | etke.cc-only platform UI; inert unless `etkeccAdmin` is configured |
| `src/entrypoints/` | two HTML entrypoints: the app and `/auth-callback` |
| `docs/` | user-facing guides; `docs/apis.md` is the endpoint inventory |
| `dist/` | generated by the build; never edit |

## Conventions

- Data CRUD and admin actions belong in `src/providers/`; components use data-provider hooks instead of `fetch`. `jsonClient` refreshes tokens and maps Matrix errors, so route authenticated admin calls through it.
- MAS rotates refresh tokens, so refresh stays single-flight through `refreshAccessToken()`; a second refresh path revokes the first caller's token.
- Users exist on two surfaces in MAS mode: the Synapse profile PUT and the MAS admin API. New user fields or actions need both branches in `src/providers/data/lifecycle.ts` and the MAS resources, or they silently no-op in one mode.
- `isMAS()` is a synchronous localStorage read for non-React code; components use `useIsMAS()` so they re-render. Resources are registered by `initResources()` at login and on reload.
- i18n: add the key to `src/i18n/types.d.ts`, `en/<domain>.ts`, and all nine other locales in the same change; no English stubs outside `en`.
- Lists use the local `Datagrid` wrapper (`src/components/layout/Datagrid.tsx`, built on `DatagridConfigurable` with accessible rows). Do not migrate lists to react-admin `DataTable`.
- Log via `createLogger()` from `src/utils/logger.ts`, passing a short scope name. Tests silence `console.log` globally.
- Comments: one line, max 120 chars, no consecutive `//` lines or `/* */` blocks; `just test` enforces it.

## Testing

- Vitest + jsdom; tests sit next to the code as `*.test.ts(x)`, and `yarn test` runs the suite.
- `src/vitest.setup.ts` gives each test fresh `localStorage`/`sessionStorage` and registers `vitest-axe` matchers.
- Provider tests mock `jsonClient`/`httpClient` from `src/providers/http.ts`; component tests render inside `<AdminContext>` with a mocked data provider (pattern: `src/pages/LoginPage.test.tsx`).
- Bug fix: write the regression test first; the handoff gate is `just test`.

## Landmines

- MAS detection is decided once per login (`RaStore.isMAS`, from the token endpoint plus a MAS admin health check). Change it only through `detectAndSetMAS()`/`setIsMAS()`, then call `initResources()`.
- Session state is localStorage: `base_url`, `access_token`, `refresh_token`, `token_endpoint`, `RaStore.isMAS`, `RaStore.locale`. Renaming or clearing a key breaks re-login or MAS detection; `ClearConfig()` wipes all of it on logout.
- The title base is `document.head.dataset.baseTitle`, written in `src/index.tsx`, `src/pages/auth-callback.tsx`, and `src/components/layout/AdminLayout.tsx`, read by `useDocTitle()`. Keep all four in sync.
- `config.json` is fetched relative to `import.meta.env.BASE_URL`; a build with the wrong `--base` 404s config and assets. `vite.config.ts` also relocates the app entrypoint to the dist root and the auth callback under its own directory, and rewrites asset URLs.
- `src/components/etke.cc/*` must stay harmless on self-hosted installs; gate on `etkeccAdmin` or `instanceConfig.disabled`, never on a reachable etke.cc backend.

## Boundaries

- Always: `just test` before handoff; update `docs/` when behavior or configuration changes; keep every locale in sync.
- Ask first: new dependencies, new admin API endpoints, auth or token-storage changes, react-admin/MUI major upgrades.
- Never: edit `dist/` by hand; commit a real homeserver URL, token, or `config.json` secret; hardcode user-facing strings outside the i18n catalogs.
